## 30-2. 데이터 원칙

- 모든 데이터는 JSON + **스키마 검증** (로드 시, CI에서). 스키마 파일은 `src/data/schema/`
- 모든 문자열은 키로 참조하고 실제 한국어는 `src/i18n/ko/*.json`
- 콘텐츠 id는 영어 snake_case, 절대 재사용 금지 (저장 파일 호환). 스킬 id는 17-1 표, 죄 "분노"는 `wrath`(표시명 "분노(죄)")
- **기간 필드 규칙**: 기간, 주기, 빈도를 담는 모든 필드는 `{ value, scale }` 형식이고 `scale`은 `absolute | season | lifespan | per_life` 중 하나 (29-0). `scale`이 없으면 스키마 오류
- **사건 카드 필수 필드**: 대상 가용 조건, 부재 시 처리, 재등장 대기, 인생당 상한, 월드 행동이 있으면 행동 계약(대체 결과 포함), 평판 4종 변화량 (24-1)
- 사건 카드와 무드렛은 **검사 스크립트**로 도달 가능성 확인: 조건이 서로 모순이라 영원히 안 나오는 카드 탐지 (24-4 3단 검사)
- 콘텐츠 대량 작성은 분류별로 나눠 병렬 작성 가능. 단, 톤 교정 패스는 한 번에 한 사람(에이전트)이 전체를 보고 통일. 톤과 수위는 00장 "수위와 톤" 기준 (17세 이용가), 카드마다 수위 등급 필드(전연령/15/17)

## 30-3. 저장 파일

- 구조: 월드(마을, NPC, 부지, 정책, 날씨, 달력, 마을 재화 장부, 영주 금고) + 조작 가문 + 연대기(이미지는 별도 파일) + 설정 + **장면 스택 전체**(27-7) + 인물별 상태 기계 값과 LOD 등급(13-6, 13-8) + RNG 상태 + **입력 로그**(플레이어 의도, AI 결과)
- **저장 시점**: 틱 경계에서만. 전투 교전 중 수동 저장은 라운드 경계까지 지연(최대 약 3초), 자동 저장은 활성 차단 장면과 교전이 없을 때까지 미룸 (27-5)
- **입력 로그**: AI 응답과 대화 입력의 의도 태그는 게임 입력으로 취급. `{요청 id, 요청 틱, 도착 틱, 결과 JSON}`을 기록하고, 재생과 불러오기 후 재실행은 네트워크가 아니라 로그에서 읽음 (25-3)
- 저장 형식 버전 + 마이그레이션 함수 체인
- 크기 목표: 연대기 이미지 제외 10MB 이하
- 저장/불러오기 후 월드 상태 해시가 같아야 함 (테스트). 같은 시드 + 같은 입력 로그 재생 = 같은 해시
