# 가문 연대기 제작 프롬프트

> [!info] 방식
> - 참고: `Opus 5.5로 퀄리티 좋은 게임 뽑기 - 자료 정리 검증본.md`
> - 오리지널 기획이라 통째 비교할 레퍼런스가 없음 → **브리프 방식(7-1)으로 마일스톤을 쌓고, 개선 리스트 루프(7-3)로 재미를 잡음**
> - 범위가 커서 **세션 하나에 마일스톤 1~2개**. 세션 사이에 직접 플레이하고 메모를 남겨 다음 세션에 넣음
> - 비주얼은 부분 레퍼런스(Epic RPG World 공식 샘플 이미지)로 블라인드 비교 가능 (프롬프트 V)
> - 모든 세션 프롬프트에 "범위 줄이지 말 것"이 들어감. 에이전트가 기능을 빼려 하면 멈추고 보고하게 함

## 준비 (사람이 할 일)

1. 폴더 만들기 (예: `Documents\hearth-and-kin`), 이 폴더 내용 복사 (`CLAUDE.md`, `BRIEF.md`는 루트, 나머지는 `docs/`)
2. Epic RPG World Collection을 유니티 에셋 스토어에서 받아 `assets/vendor/epic-rpg-world/`에 (`.unitypackage` 그대로 둬도 됨. 에이전트가 풀 수 있음, 04 문서 1절). `docs/04L_LPC_에셋_목록.md`의 LPC 에셋과 `docs/04_에셋_목록.md` 5절(공통 무료), 5-1절(유료 UI/음악 등, 필요한 만큼)을 받아 `assets/vendor/<팩>/`에 풀기
3. `git init`, 첫 커밋
4. 폰트: 넥슨 워헤이븐체를 받아 `assets/fonts/`에 (04 문서 링크)
5. 생성형 AI 이미지를 쓰려면 `GEMINI_API_KEY` 준비 (threejs-image-generator 스킬). 없으면 에이전트가 픽셀 스크립트로만 작업
6. 모델 Opus 5.5. 구현 세션 effort **high**, 개선 루프 **medium**
7. AI 대화(M15)를 쓰려면 Anthropic API 키, 갤러리(M16)를 쓰려면 Cloudflare 계정 준비

## 프롬프트 0. 기획 검토 (코딩 전, 2~3회 반복)

```
docs/의 GDD 전체(00, gdd/10~33)와 BRIEF.md를 코딩 에이전트 입장에서 검토해줘. 코드는 쓰지 마.
기능을 빼자는 제안은 하지 마. 전부 구현한다는 전제에서 검토할 것.

찾을 것:
- 구현하려면 결정이 필요한데 문서에 없는 규칙 (시스템 간 충돌 규칙 포함. 예: 임신 중 역병, 유령과 상속)
- 수치끼리 모순되거나 29장 밸런스 목표와 맞지 않을 것 같은 곳 (대략 계산 근거와 함께)
- 문서끼리 다르게 말하는 곳
- 마일스톤 통과 조건 중 자동으로 측정할 수 없는 것과 측정 방법 제안
- assets/vendor/의 실제 파일을 열어 보고: docs/04_에셋_목록.md 4절 "직접 만들어야 하는 것" 목록(GDD 28-2가 가리키는 곳)이 맞는지, 그 밖에 빠진 스프라이트
- 가장 먼저 무너질 것 같은 시스템 3개와 이유, 그리고 무너지지 않게 할 설계 보강안

형식: [문서 위치] 문제 → 제안. 중요도 순, 최대 30개.
```

## 세션 프롬프트 공통 틀

아래 `{…}`만 바꿔서 세션마다 사용

```
/threejs-game-director

BRIEF.md의 {M번호들}을 구현해줘. 관련 설계는 docs/gdd/{문서 번호들}.
현재 상태는 TASKS.md와 artifacts/game-progress.md 참고.

범위: GDD에 적힌 기능을 줄이거나 "나중에"로 미루지 말 것. 기술적으로 막히면 빼지 말고 대안 설계를 DECISIONS.md에 적은 뒤 나에게 보고.

[지난 세션 플레이 메모]
{직접 플레이하며 적은 문제. 없으면 "없음"}
위 메모를 먼저 처리하고 항목별로 무엇을 고쳤는지 한 줄씩 보고.

진행:
- 마일스톤마다 BRIEF.md 5장 통과 조건을 스크린샷, 테스트 출력, 헤드리스 수치로 확인하고 TASKS.md 체크
- 이전 마일스톤 회귀 테스트가 계속 통과해야 함
- 마일스톤이 끝날 때마다 새 컨텍스트 서브에이전트에게 이번에 바뀐 src/sim/ 코드 리뷰를 맡기고, 지적은 근거 확인 후 반영
- 콘텐츠(카드, 문장, 무드렛)는 이번 시스템 몫의 30% 이상 채울 것
- 스코어카드는 BRIEF.md 1장 마지막 항목처럼 2D 기준으로 바꿔 읽을 것

완료 조건: BRIEF.md 5장의 {M번호들} 통과 조건 전부 + 콘솔 에러 0 + 성능 예산 충족.

쓰지 말 것: BRIEF.md 7장.
파괴적 작업, 에셋 구매/다운로드가 필요할 때, 게임 설계를 바꿔야 할 때만 멈추고 물어볼 것.
```

## 프롬프트 V. 비주얼 비평 (M1 이후 아무 때나)

```
화면 구성 품질만 비교하는 비평을 돌려줘.

- 레퍼런스: Epic RPG World 스토어 페이지의 미리보기 이미지 (유니티 에셋 스토어 또는 itch.io 제작자 페이지)
- 비교 대상: 우리 게임의 같은 종류 장면(오두막 실내, 장터, 공방)을 같은 줌으로, captureState + hideUI로 찍은 것
- 비평가는 새 컨텍스트 서브에이전트. 우리 설명이나 코드는 주지 말고, 이름과 순서를 섞은 두 이미지만 줄 것
- 비평가는 "더 완성된 장면" 하나를 고르고, 진 쪽이 진 이유를 위치와 함께 5개 이내로 지적. 점수는 매기지 않음
- 우리가 지면 고치고 다시 비교. 장면마다 최대 3라운드. 그래도 지면 남은 지적을 TASKS.md에 적고 멈출 것
```

## 프롬프트 L. 개선 리스트 루프 (세션 3 이후, 세션 사이마다)

```
지금 상태에서 개선할 점 10개를 뽑아줘.
기준: 플레이어가 20분 플레이할 때 재미와 이해를 가장 크게 해치는 순서.
각 항목: [어디서 / 무엇이 / 왜 / 작업량 소·중·대].
스텁만 있는 시스템, 연결 안 된 이벤트, GDD에 있는데 아직 안 된 기능도 포함.
```

사람: 20분 직접 플레이 → 내 목록 → 두 목록에서 5~6개 선택

```
이번엔 이것만 해줘:
1. …
각 항목의 완료 기준은 [한 줄]. 끝나면 항목별 변경 내용과 확인 방법을 보고.
```

**플레이 체크 목록**
- 인물이 내가 안 시킨 행동을 했을 때 이유가 보였나 (무드렛, 속마음)
- 신분 차이가 실제로 느껴졌나 (옷, 출입, 대화, 처벌)
- 살림(저장고, 땔감)과 농사가 부담이면서도 재미있었나, 아니면 귀찮기만 했나
- 전투와 마법이 가족 이야기를 살렸나, 아니면 딴 게임처럼 겉돌았나
- 시작 신분마다 플레이 느낌이 달랐나
- 마을이 살아 있다고 느꼈나 (소문, 일과, 스토리 진행)
- 연대기를 다시 읽고 싶었나

## 운영 팁

- 도중 방향 수정은 새로 시작하지 말고 그 세션에 메시지로 덧붙이기
- 컨텍스트가 압축되면 "TASKS.md와 artifacts/game-progress.md부터 다시 읽고 이어서"
- 세션이 4시간을 넘기거나 같은 문제를 3번 고쳐도 안 되면 멈추고 보고하도록 CLAUDE.md에 적어 둠
- 결과물과 함께 BRIEF, DECISIONS, 개선 루프 기록을 남기면 "기획을 AI로 검증한 과정" 포트폴리오가 됨
